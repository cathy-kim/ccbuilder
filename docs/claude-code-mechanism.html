Claude Code 동작 메커니즘

Memory(rules) / Skills / Subagents / Hooks가 각각 어떤 경로로 Anthropic Messages API 요청에 도달하는지, 그리고 한 번의 사용자 입력이 어떻게 여러 번의 LLM 호출로 전개되는지를 공식 정의 기준으로 시각화한 문서.

정확도 기준. 확장 메커니즘(Skills·Subagents·Hooks·Memory·Rules)은 공식 문서(code.claude.com/docs, ccbuilder v2.22.0 / CC v2.1.85) 기준입니다. 와이어 레벨(system 블록·cache_control·tools 직렬화)은 Anthropic Messages API 표준 동작과 claude-code-system-prompts 공개 자료 기준이며, 시스템 프롬프트의 정확한 조립 순서 등 일부는 비공개 구현 영역이라 구현 영역 표시로 구분했습니다.

0개요 — Claude Code 확장 시스템

Claude Code는 LLM(Claude)을 감싸는 에이전트 하네스입니다. 7가지 확장 요소가 각자 다른 방식으로 "모델에게 무엇을 보여줄지(컨텍스트)"와 "모델이 무엇을 할 수 있는지(도구)", "언제 개입할지(제어)"를 결정합니다.

요소역할LLM에 닿는 방식위치

핵심: 각 요소는 LLM 요청의 서로 다른 부분에 도달합니다. rules/memory와 skill 본문은 컨텍스트로, 도구·MCP는 tools로, subagent는 별도 요청으로, hook은 요청을 만들기 전후에 개입합니다.

2LLM API 요청 구조 Anthropic Messages API

Claude Code는 매 턴마다 Anthropic POST /v1/messages를 호출합니다. 요청은 크게 system · tools · messages 세 덩어리이며, 큰 안정 구간(system+tools+memory)은 prompt caching으로 재사용합니다.

요청 body 골격

{
  "model": "claude-opus-4-6",
  "max_tokens": 64000,
  "system": [                       // 블록 배열 — cache_control 지원
    { "type":"text", "text":"<정체성 + 도구사용 지침 + 환경 컨텍스트>",
      "cache_control": {"type":"ephemeral"} },           // ← breakpoint
    { "type":"text", "text":"<CLAUDE.md / rules 메모리>" }
  ],
  "tools": [                        // 내장 + MCP 도구
    { "name":"Read", "description":"…", "input_schema":{…} },
    { "name":"Edit", "…":"…",
      "cache_control": {"type":"ephemeral"} }            // ← 마지막 도구에 breakpoint
  ],
  "tool_choice": {"type":"auto"},
  "messages": [
    { "role":"user",      "content":[ {"type":"text","text":"…"} ] },
    { "role":"assistant", "content":[ {"type":"thinking",…}, {"type":"tool_use",…} ] },
    { "role":"user",      "content":[ {"type":"tool_result","tool_use_id":"…","content":[…],
                                        "cache_control":{"type":"ephemeral"}} ] }  // ← rolling
  ],
  "thinking": {"type":"enabled","budget_tokens": …},   // extended thinking 시
  "stream": true
}

Prompt Caching — 최대 4개 breakpoint

Anthropic API는 요청당 최대 4개의 cache_control: {"type":"ephemeral"} 마커를 허용합니다(TTL 기본 5분, 옵션 1시간). Claude Code는 변하지 않는 큰 prefix를 캐시해 반복 턴 비용을 줄입니다. 전형적 배치:

flowchart LR
  A["system blocks
(정체성+지침+메모리)"] -->|"breakpoint 1~2"| B["tools 배열"]
  B -->|"breakpoint 3"| C["대화 히스토리 prefix"]
  C -->|"breakpoint 4 (rolling)"| D["최신 tool_result / user turn"]
  classDef cached fill:#eef1fd,stroke:#2347d9,color:#1b1b18;
  classDef fresh fill:#fbf0e6,stroke:#b54708,color:#1b1b18;
  class A,B,C cached;
  class D fresh;
파란 = 캐시 적중(저비용 재사용), 주황 = 매 턴 새로 들어가는 부분. 캐시 적중 시 cache_read_input_tokens로 청구.

헤더 · 인증 · 스트리밍

항목내용
엔드포인트POST https://api.anthropic.com/v1/messages

구현 영역 주의. cache_control breakpoint의 정확한 개수·위치, system 텍스트 원문은 비공개 구현이며 버전마다 달라질 수 있습니다. 위 골격은 Anthropic Messages API 규격 + 공개된 prompt-caching 모범 패턴에 근거한 대표 구조입니다.

3에이전틱 루프 — "1 입력 → N회 LLM 호출"

사용자 입력 한 번은 모델이 도구를 그만 쓸 때(end_turn)까지 여러 번의 LLM 호출로 전개됩니다. 매 호출마다 system·tools는 (대개 캐시로) 재사용되고 messages만 누적됩니다.

flowchart TD
  U["사용자 입력"] --> UPS["UserPromptSubmit 훅
(차단·컨텍스트 주입 가능)"]
  UPS --> SC["스킬 자동 활성화 판단
(description 매칭)"]
  SC --> BR
  subgraph LOOP["에이전틱 루프"]
    BR["요청 조립: system + tools + messages
(prompt caching)"]
    BR --> CALL["Claude 호출 (stream)"]
    CALL --> Q{"응답에 tool_use 있나?"}
    Q -- "없음 (end_turn)" --> BREAK["루프 종료"]
    Q -- "있음" --> FOR
    subgraph FOR["각 tool_use 처리"]
      PRE["PreToolUse 훅
allow/deny/ask · updatedInput"]
      PRE --> PERM["권한 검사 (PermissionRequest 훅)"]
      PERM --> EX["도구 실행 (또는 Task→Subagent)"]
      EX --> POST["PostToolUse / PostToolUseFailure 훅"]
      POST --> APP["tool_result를 messages에 추가"]
    end
    FOR --> CC{"컨텍스트 한도 근접?"}
    CC -- "예" --> CMP["auto-compact
(PreCompact → 요약 → PostCompact)"]
    CC -- "아니오" --> BR
    CMP --> BR
  end
  BREAK --> STOP["Stop 훅
(작업 계속 강제 가능)"]
종료 조건: 모델이 tool_use 없이 응답(end_turn). Stop 훅이 decision:"block"이면 계속 작업하도록 되돌릴 수 있음.
Auto-compaction. 컨텍스트가 한도에 근접하면 오래된 대화를 요약본으로 치환해 토큰을 회수합니다. 트리거 비율은 CLAUDE_AUTOCOMPACT_PCT_OVERRIDE로 조정 가능하며, PreCompact/PostCompact 훅이 전후에 발화합니다.

5Skills — Progressive Disclosure

Skill의 핵심은 점진적 공개입니다. 메타데이터(name+description)는 항상 로드되어 카탈로그를 이루고, 본문은 활성화될 때만 컨텍스트에 주입되며, 보조 리소스는 필요할 때 도구로 읽힙니다.

flowchart TD
  subgraph LOAD["3단계 로딩 (토큰 절약)"]
    L1["① 메타데이터: name + description
(항상 컨텍스트에 존재 = 카탈로그)"]
    L2["② 본문: SKILL.md (≤500줄)
(활성화 시 주입)"]
    L3["③ 리소스: references/ scripts/
(필요 시 Read 도구로 로드)"]
    L1 --> L2 --> L3
  end
  TRIG{"활성화 트리거"}
  T1["모델 자동 호출
(description 매칭)"] --> TRIG
  T2["사용자 / 슬래시 호출"] --> TRIG
  T3["Skill 도구 호출"] --> TRIG
  TRIG --> L2
  L2 --> CTX["본문 + 치환된 ARGUMENTS
+ 백틱 명령 동적 컨텍스트 → 대화에 주입"]
  CTX --> FORK{"context: fork?"}
  FORK -- "예" --> SUB["별도 서브에이전트에서 실행"]
  FORK -- "아니오" --> MAIN["현재 대화에서 실행"]
우선순위: Enterprise > Personal(~/.claude/skills) > Project(.claude/skills) > Plugin. 동명 스킬은 상위가 덮어씀.

SKILL.md frontmatter & 치환

필드의미
name / description필수. description은 자동 활성화 키워드 역할
userInvocablefalse면 사용자 메뉴에서 숨김(모델 전용)
disable-model-invocationtrue면 자동 호출 끔(수동 /만)

치환: $ARGUMENTS, $1·$2, $ARGUMENTS[0], ${CLAUDE_SESSION_ID}. 동적 주입: !`git status --short`처럼 백틱 명령 결과를 실행 시점에 삽입.

슬래시 커맨드 = Skills. 커스텀 슬래시 명령은 Skills 시스템으로 통합되었습니다. .claude/commands/*.md도 여전히 동작하지만 skills/가 권장됩니다.

6Subagents — Task 도구 / 별도 200k 컨텍스트

서브에이전트는 Task 도구로 호출되어 독립된 200k 컨텍스트 창에서 자기만의 에이전틱 루프를 돌고, 기본적으로 최종 결과를 동기 tool_result로 부모에게 반환합니다.

sequenceDiagram
  participant P as 메인 대화
  participant A as Claude (부모)
  participant SUB as Subagent (별도 200k)
  participant SA as Claude (서브)
  P->>A: 사용자 작업
  A-->>P: Task 도구 호출 {subagent_type, prompt, model?, run_in_background?}
  Note over SUB,SA: 부모 히스토리 비상속 · 자체 system + 제한된 tools
  loop 서브 에이전틱 루프 (≤ maxTurns)
    SUB->>SA: 요청 (자체 컨텍스트)
    SA-->>SUB: tool_use / 텍스트
  end
  alt 기본 (동기)
    SUB-->>A: 최종 결과를 tool_result로 반환
  else run_in_background:true
    SUB-->>A: output_file 경로 → Read로 회수
  end
제약: 최대 동시 10개 · 중첩 불가(서브가 또 서브 호출 X) · 서브에이전트도 auto-compaction 지원.

7Hooks — 24개 라이프사이클 이벤트

훅은 셸/HTTP/프롬프트/에이전트 핸들러로 라이프사이클에 개입해 도구를 차단·수정하거나 컨텍스트를 주입합니다. LLM 요청을 직접 만들진 않지만, 요청 전후와 도구 실행 전후에 끼어듭니다.

flowchart TD
  S["SessionStart"] --> U["UserPromptSubmit
(exit 2로 차단)"]
  U --> P1["PreToolUse
permissionDecision: allow/deny/ask · updatedInput"]
  P1 --> PR["PermissionRequest
(권한 대화상자)"]
  PR --> EXE["도구 실행"]
  EXE --> SS["SubagentStart/Stop
(Task인 경우)"]
  SS --> P2["PostToolUse / PostToolUseFailure
(decision: block)"]
  P2 --> ML{"도구 더 있나?"}
  ML -- "예" --> P1
  ML -- "아니오" --> ST["Stop / StopFailure
(decision: block → 계속)"]
  CMP["PreCompact / PostCompact"] -.-> P1
  IL["InstructionsLoaded"] -.-> S
전체 24개 이벤트 중 한 턴에서 자주 발화하는 순서. 그 외: Notification·TeammateIdle·TaskCreated/Completed·CwdChanged·FileChanged·Worktree*·Elicitation* 등.

설정 · 핸들러 · 결정 제어

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash|Edit|Write",          // tool_name 정규식 (없거나 * = 전체)
      "hooks": [{ "type":"command", "command":"./hooks/validate.sh" }]
    }],
    "Stop": [{ "type":"command", "command":"./hooks/on-stop.sh" }]
  }
}
핸들러 type동작
command셸 스크립트. stdin에 JSON, exit code + stdout JSON 응답
httpURL로 JSON POST(셸 불필요)
prompt단일 LLM 호출 → {ok, reason}
agent서브에이전트(도구 접근)
async: true백그라운드(command). 차단 안 함, 다음 턴에 결과 주입
제어 필드효과
hookSpecificOutput.permissionDecisionPreToolUse: allow / deny / ask
hookSpecificOutput.updatedInput도구 입력 교체 (PreToolUse)
hookSpecificOutput.additionalContext컨텍스트 주입
top-level decision: "block"PostToolUse·Stop 등: 차단/계속 강제
exit code0=성공, 2=차단, 기타=비차단

9End-to-End 시나리오

사용자가 프롬프트를 보내고, 그게 스킬을 자동 활성화시키고, 모델이 서브에이전트를 호출하고, 훅이 도구를 검증하는 전 과정.

sequenceDiagram
  participant U as 사용자
  participant CC as Claude Code 하네스
  participant A as Claude (메인)
  participant SUB as Subagent (별도 200k)
  U->>CC: 프롬프트 입력
  CC->>CC: UserPromptSubmit 훅 (차단·컨텍스트 주입)
  CC->>CC: description 매칭 → Skill 활성화 → 본문 주입 (progressive disclosure)
  CC->>A: 요청 #1 · system[정체성+환경+CLAUDE.md+스킬본문] / tools / messages
  A-->>CC: Task 도구 호출 (subagent_type, prompt)
  CC->>CC: PreToolUse 훅 → 권한 검사
  CC->>SUB: 별도 200k 컨텍스트에서 서브 루프 실행
  SUB-->>CC: 최종 결과
  CC->>CC: PostToolUse 훅 → tool_result 구성
  CC->>A: 요청 #2 · messages에 tool_result 누적
  A-->>CC: 최종 답변 (tool_use 없음 = end_turn)
  CC->>CC: Stop 훅 (계속 강제 가능) · 한도 근접 시 compact
  CC-->>U: 응답
  1. Memory/Rules — 매 요청의 system에 주입(상위 계층 우선, @import·rules 포함).
  2. Skill — description 매칭으로 활성화되면 본문이 컨텍스트로 주입(progressive disclosure). context:fork면 서브에이전트로.
  3. Subagent — Task 도구로 별도 200k 컨텍스트에서 독립 루프, 기본 동기 tool_result 반환.
  4. Hook — UserPromptSubmit·PreToolUse·PostToolUse·Stop 등 라이프사이클에 개입해 차단·수정·주입.
  5. Prompt caching — system+tools+메모리 prefix를 캐시해 반복 호출 비용 절감(최대 4 breakpoint).

10인증 & 과금 — API 키 vs OAuth 구독

CLI를 구독(Claude Pro/Max)으로 쓰든 API 키로 쓰든 요청 body·도구·에이전틱 루프는 100% 동일합니다. 달라지는 건 ① 인증 헤더 ② 과금 ③ rate limit 체계, 단 3가지입니다.

인증 모드 3가지

실행계정 / 경로과금
claude auth login / /login (기본)Claude.ai 구독 (Pro/Max) · OAuth구독 한도 — 크레딧 소진 안 함
claude auth login --consoleAnthropic Console · OAuth토큰당 API 과금
ANTHROPIC_API_KEY=…API 키 (헤드리스/CI)토큰당 API 과금
본질은 "OAuth냐 API키냐"가 아닙니다. 구독도 내부적으로 OAuth 토큰을 씁니다. 진짜 갈림길은 구독 한도로 쓰느냐 vs 토큰당 과금하느냐입니다. 그냥 claude 실행 = 구독(①)이 기본.

OAuth 흐름 (PKCE)

sequenceDiagram
  participant U as 사용자
  participant CLI as claude CLI
  participant B as 브라우저
  participant AUTH as Anthropic 인증 서버
  U->>CLI: claude /login
  CLI->>CLI: PKCE 챌린지 생성
  CLI->>B: 인증 페이지 열기 (claude.ai)
  U->>B: "승인" 클릭
  B->>CLI: authorization code (로컬 콜백 포트)
  CLI->>AUTH: code → 토큰 교환
  AUTH-->>CLI: access_token + refresh_token
  CLI->>CLI: 로컬 보관 (macOS Keychain / ~/.claude/.credentials.json)
  Note over CLI: 이후 매 호출 Authorization: Bearer access_token
  CLI->>AUTH: access_token 만료 시 refresh_token으로 자동 갱신
access token은 단기 만료 → refresh token으로 백그라운드 자동 갱신(재로그인 불필요). claude auth status/logout으로 상태 확인·폐기. 저장 경로는 구현 영역

매 요청에서 달라지는 것 / 그대로인 것

POST https://api.anthropic.com/v1/messages          // 엔드포인트 동일
  anthropic-version: 2023-06-01                       // 동일
  anthropic-beta: <기능 플래그>                        // 동일 (+OAuth 식별 플래그)
- x-api-key: sk-ant-...           (API 키 모드)
+ Authorization: Bearer <oauth>   (구독 모드)          // ← 여기만 교체
  body: { model, system[], tools[], messages[] }      // 완전히 동일
그대로 (변화 없음)달라짐
system / tools / messages 구조인증 헤더 (Bearer ↔ x-api-key)
prompt caching (최대 4 breakpoint)과금 (구독 한도 ↔ API 크레딧)
에이전틱 루프 · Hook · Subagentrate limit (5h/주간 ↔ API rate limit)
시스템 프롬프트가 구독 등급을 인지합니다. 공개된 claude-code-system-prompts에는 GET_SUBSCRIPTION_TYPE_FN()으로 분기하는 부분이 있어(예: Task 도구 설명이 pro 여부로 달라짐) 같은 버전이라도 구독 등급에 따라 프롬프트가 미세하게 다를 수 있습니다.

CI / 헤드리스

브라우저 OAuth가 불가능한 환경에서는 claude setup-token으로 장기 토큰을 발급하거나 ANTHROPIC_API_KEY(API 결제)를 사용합니다. --bare(-p 경량 모드)는 API 키가 필수입니다.
