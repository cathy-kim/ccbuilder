# Claude Code Extension Builder

**Version**: 2.2.0
**Last Updated**: 2026-01-24

## 목적

Claude Code 확장 기능(Skills, Agents, Hooks) 개발 질문 답변 및 구현 가이드 제공.

---

## 핵심 변경 사항 (2025-12 ~ 2026-01)

### Deprecated (사용 중지)

| Deprecated | 대체 방법 |
|------------|-----------|
| `output styles` | `--system-prompt-file` 또는 `plugins` 사용 |
| `legacy SDK entrypoint` | `@anthropic-ai/claude-agent-sdk`로 마이그레이션 |
| `includeCoAuthoredBy` 설정 | 새 `attribution` 설정 사용 |
| Windows `C:\ProgramData\ClaudeCode\` | `C:\Program Files\ClaudeCode\`로 이동 |

### Slash Commands & Skills 통합

```
# 이전: commands/ 폴더와 skills/ 분리
.claude/commands/frontend/component.md  → /frontend:component

# 현재: Skills가 slash commands 기능 포함
.claude/skills/my-skill/SKILL.md        → /my-skill (userInvocable: true 시)
```

**중요**: `commands/` 폴더는 여전히 지원되지만, 새 구현은 `skills/` 폴더 사용 권장.

## 1. Skills (스킬)

### 위치
- `~/.claude/skills/` (전역)
- `.claude/skills/` (프로젝트)

### 최신 SKILL.md Frontmatter (v2.1+)

```yaml
---
name: my-skill                    # 필수
description: "설명 + 자동 활성화 키워드"  # 필수
userInvocable: true               # /my-skill 로 직접 호출 가능

# 도구 제한 (CLI에서만 작동, SDK는 별도 설정 필요)
allowed-tools:
  - Read
  - Grep
  - Glob
  - Edit

# 실행 컨텍스트 (선택)
context: fork                     # 별도 컨텍스트에서 실행

# 에이전트 지정 (선택)
agent: backend                    # 특정 에이전트로 실행

# 다른 스킬 함께 로드 (선택)
skills:
  - design-system
  - testing-patterns

# 내장 Hooks (선택)
hooks:
  - type: PreToolUse
    tool: Bash
    script: ./hooks/validate.sh
  - type: Stop
    script: ./hooks/cleanup.sh
    once: true                    # 세션당 1회만

# 추가 옵션
version: "1.0.0"                  # 버전 추적용
disable-model-invocation: false   # true면 자동 호출 방지, 수동만 가능
mode: false                       # true면 "Mode Commands" 섹션에 표시
---

# My Skill

## 목적
스킬의 목적 설명

## 지침
1. 첫 번째 단계
2. 두 번째 단계

## 참조
상세 내용은 `references/` 폴더 참조
```

### Frontmatter 옵션 정리

| 옵션 | 타입 | 설명 | 기본값 |
|------|------|------|--------|
| `name` | string | 스킬 이름 | **필수** |
| `description` | string | 설명 + 자동 활성화 키워드 | **필수** |
| `userInvocable` | boolean | `/skill-name`으로 직접 호출 | `true` |
| `allowed-tools` | string[] | 허용된 도구 목록 | 모든 도구 |
| `context` | "fork" | 별도 컨텍스트에서 실행 | - |
| `agent` | string | 실행할 에이전트 타입 | - |
| `skills` | string[] | 함께 로드할 다른 스킬 | - |
| `hooks` | object[] | 내장 Hook 정의 | - |
| `version` | string | 버전 추적용 메타데이터 | - |
| `disable-model-invocation` | boolean | Claude 자동 호출 방지 | `false` |
| `mode` | boolean | Mode Commands 섹션에 표시 | `false` |

### Hot Reload

```bash
# 스킬 수정 시 자동 반영 - 재시작 불필요!
echo "수정" >> .claude/skills/my-skill/SKILL.md
# 즉시 활성화됨
```

### Progressive Disclosure (500줄 규칙)

```
my-skill/
├── SKILL.md          # < 500줄 (개요만)
└── references/       # 상세 가이드
    ├── topic-1.md
    └── topic-2.md
```

## 2. Hooks (훅)

### Hook 이벤트 (v2.1+ 최신)

| Event | 트리거 시점 | Block 가능 | 주요 입력 필드 |
|-------|------------|-----------|---------------|
| **SessionStart** | 세션 시작/재개 | No | `session_id`, `agent_type` |
| **SessionEnd** | 세션 종료 | No | `session_id` |
| **UserPromptSubmit** | 프롬프트 제출 전 | No | `prompt` |
| **PreToolUse** | 도구 호출 전 | Yes (exit 2) | `tool_name`, `tool_input`, `tool_use_id` |
| **PostToolUse** | 도구 호출 후 | No | `tool_name`, `tool_result` |
| **PermissionRequest** | 권한 다이얼로그 | Yes (exit 2) | `permission_type` |
| **Stop** | Claude 응답 완료 | Yes (block) | `stop_reason` |
| **SubagentStop** | 서브에이전트 완료 | No | `subagent_result`, `agent_id`, `agent_transcript_path` |
| **PreCompact** | compact 전 | No | - |
| **Notification** | 알림 발생 | No | `notification` |

### Exit Codes

| Exit Code | 효과 |
|-----------|------|
| **0** | 정상 진행 (stdout → Claude에 표시) |
| **1** | 에러 (stderr → 사용자에게 표시) |
| **2** | 액션 차단 (PreToolUse/PermissionRequest만) |

### settings.json 설정

```json
{
  "hooks": {
    "SessionStart": [
      {
        "type": "command",
        "command": "echo 'Session started'"
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash|Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "./hooks/validate.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "type": "command",
        "command": "./hooks/on-stop.sh"
      }
    ],
    "SubagentStop": [
      {
        "type": "command",
        "command": "./hooks/subagent-complete.sh"
      }
    ]
  }
}
```

### Matcher 패턴 (PreToolUse/PostToolUse/PermissionRequest)

| 패턴 | 매칭 대상 |
|------|----------|
| `"Bash"` | Bash 도구만 |
| `"Edit\|Write"` | Edit 또는 Write |
| `"*"` | 모든 도구 |

### 주의사항

- **SessionStart/SessionEnd/Notification**: TypeScript SDK에서만 지원 (Python SDK 미지원)
- **Stop hook**: `block` 반환 시 Claude가 계속 작업 (reason 필수)
- **SubagentStop**: `agent_transcript_path`로 전체 transcript 접근 가능

## 3. Subagents (서브에이전트)

### 내장 Subagent 타입

| subagent_type | 용도 | 특징 |
|---------------|------|------|
| `Explore` | 코드베이스 탐색 | 읽기 전용, Haiku 기반, 빠름 |
| `Plan` | 구현 계획 설계 | 아키텍처 분석 |
| `general-purpose` | 복잡한 멀티스텝 작업 | 모든 도구 접근 |
| `claude-code-guide` | Claude Code 문서 조회 | 공식 문서 검색 |

### 커스텀 에이전트 정의 (.claude/agents/)

```yaml
---
name: frontend-developer
description: "React/Next.js 프론트엔드 개발 전문"
model: sonnet                     # sonnet | opus | haiku

# 도구 제한
allowed-tools:
  - Read
  - Write
  - Edit
  - Glob
  - Grep
  - Bash(npm:*)
  - Bash(npx:*)

# 스킬 연결
skills:
  - frontend-design-system
  - testing-patterns

# 내장 Hooks
hooks:
  - type: PreToolUse
    tool: Write
    script: ./hooks/lint-check.sh
---

# Frontend Developer Agent

## 역할
React/Next.js 기반 프론트엔드 개발을 담당합니다.

## 규칙
1. TypeScript 사용 필수
2. 컴포넌트는 함수형으로 작성
3. 테스트 코드 함께 작성
```

### Task Tool 사용

```typescript
// 1. 코드베이스 탐색 (빠름, 저비용)
Task({
  description: "Find auth handlers",
  prompt: "인증 관련 핸들러 파일들을 찾고 구조를 분석해줘",
  subagent_type: "Explore",
  model: "haiku"
})

// 2. 커스텀 에이전트 호출
Task({
  description: "Build React component",
  prompt: "대시보드 컴포넌트를 만들어줘",
  subagent_type: "frontend-developer"  // .claude/agents/frontend-developer.md
})

// 3. 병렬 실행 (단일 메시지에 여러 Task)
Task({ subagent_type: "frontend", prompt: "UI 작성" })
Task({ subagent_type: "backend", prompt: "API 작성" })
Task({ subagent_type: "qa-expert", prompt: "테스트 작성" })

// 4. 백그라운드 실행
Task({
  description: "Long analysis",
  prompt: "전체 코드베이스 분석",
  subagent_type: "Explore",
  run_in_background: true
})
```

### 제약 사항

| 제약 | 값 |
|------|-----|
| 최대 동시 Task | 10개 |
| Task 컨텍스트 | 200k 토큰 |
| 중첩 | 불가 (Subagent가 다른 Subagent 호출 불가) |

## 알려진 에러 및 트러블슈팅

### API Error 400: Tool Use Concurrency Issues

**에러 메시지**:
```
API Error: 400 due to tool use concurrency issues. Run /rewind to recover the conversation.
```

**실제 API 응답**:
```json
{
  "type": "invalid_request_error",
  "message": "messages.N: `tool_use` ids were found without `tool_result` blocks immediately after: toolu_xxx, toolu_yyy. Each `tool_use` block must have a corresponding `tool_result` block in the next message."
}
```

**원인**:
| 요인 | 설명 |
|------|------|
| 병렬 도구 호출 충돌 | 여러 도구가 동시 실행 중 결과가 메시지 히스토리에 누락 |
| Context 부족 상태 | `Context low (10%)` 상태에서 `/compact` 시도 시 불일치 감지 |
| 긴 세션 | 메시지 172번째 등 긴 대화에서 상태 불일치 누적 |

**즉시 해결**:
```bash
# 1. 이전 상태로 복구
/rewind

# 2. 컨텍스트 정리 (Context low 상태일 때)
/compact

# 3. 세션 재시작 (에러 지속 시)
# Ctrl+C 후 다시 claude 실행
```

**재발 방지 - Hybrid 규칙** (읽기는 병렬, 쓰기는 순차):

```typescript
// ✅ 병렬 허용 (읽기 전용)
Read("file1.ts")
Read("file2.ts")
Grep("pattern", "src/")
Glob("**/*.ts")

// ✅ 순차 필수 (쓰기 작업)
Bash("cmd1 && cmd2 && cmd3")  // 체이닝
Write("file1.ts", content)     // 완료 후
Write("file2.ts", content)     // 다음 쓰기

// ⚠️ 제한
// - 동시 Task: 최대 5개
// - Context 30% 이하: 병렬 자제
```

**상세 규칙**: [_common/tool-execution-rules.md](../_common/tool-execution-rules.md)

**로그 확인 방법**:
```bash
# 최근 세션 로그 위치
ls -lat ~/.claude/debug/ | head -5

# 에러 검색
grep -i "tool_use\|tool_result\|400" ~/.claude/debug/[session-id].txt | tail -20
```

**핵심**: 이 에러는 **Claude Code CLI 내부 버그**로, 사용자 잘못이 아님. `/rewind` 또는 새 세션으로 복구.

## 4. Orchestrator Skill (병렬 Agent 조율)

병렬 Agent를 조율하는 Orchestrator Skill 생성 시 **반드시** 참조:

| 문서 | 설명 |
|------|------|
| [orchestrator-principles.md](references/orchestrator-principles.md) | 핵심 원칙, Context Injection, AB Test 결과 |
| [orchestrator-skill-creation-guide.md](references/orchestrator-skill-creation-guide.md) | 생성 가이드, 템플릿, 체크리스트 |

### 핵심 원칙

1. **YOU ORCHESTRATE, YOU DO NOT EXECUTE** - Orchestrator는 직접 코드 작성 안함
2. **SUBAGENTS LIE. VERIFY EVERYTHING.** - 파일/빌드/테스트 모두 검증
3. **BACKWARD COMPATIBILITY IS NON-NEGOTIABLE** - 하위호환 깨짐 = 즉시 RETRY

### 필수 시스템

- **Context Injection** - Shared Context + Individual Context + Result Report
- **Mission Reminder** - 목적 망각 방지 (Goal Retention 0% → 100%)
- **Evaluation Loop** - 품질 90점까지 Continue/Modify/Retry
