## 1. Skill 생성

> 공식 문서: [references/official-docs/skill-best-practices.md](references/official-docs/skill-best-practices.md)

### 기본 구조

```markdown
---
name: my-skill
description: 트리거 키워드와 사용 시점 포함 (최대 1024자)
---

# My Skill

## 목적
이 skill이 해결하는 문제

## 사용 시점
구체적인 시나리오

## 핵심 가이드
실제 구현 가이드, 예제, 패턴
```

### Progressive Disclosure (공식 가이드)

**3단계 로딩 구조**:

| 레벨 | 로딩 시점 | 토큰 비용 | 내용 |
|------|----------|----------|------|
| **Level 1: 메타데이터** | 항상 (시작 시) | ~100 tokens/Skill | YAML frontmatter |
| **Level 2: 지침** | Skill 트리거 시 | < 5k tokens | SKILL.md 본문 |
| **Level 3+: 리소스** | 필요 시 | 사실상 무제한 | 번들 파일 |

**SKILL.md는 500줄 미만 유지:**
```
my-skill/
├── SKILL.md (< 500줄)
└── references/
    ├── detailed-guide.md
    └── examples.md
```

### Description 작성법 (공식 모범 사례)

**항상 3인칭으로 작성**:
- ✅ "Processes Excel files and generates reports"
- ❌ "I can help you process Excel files"
- ❌ "You can use this to process Excel files"

**구체적이고 키워드 포함**:
```yaml
# 좋은 예
description: Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.

# 나쁜 예
description: Helps with documents
```

### skill-rules.json 설정

```json
{
  "my-skill": {
    "type": "domain",
    "enforcement": "suggest",
    "promptTriggers": {
      "keywords": ["my-skill", "related-topic"],
      "intentPatterns": ["(create|build).*?something"]
    }
  }
}
```

**Skill 유형:**
- **Guardrail** (enforcement: "block"): 치명적 실수 방지, 보안 검증
- **Domain** (enforcement: "suggest"): 도메인 지식, 모범 사례

## 3. Hook 생성

> **P1 공식 문서**: [code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks)

### Hook 유형

| Hook | 실행 시점 | Exit 0 | Exit 2 |
|------|----------|--------|--------|
| **UserPromptSubmit** | 프롬프트 처리 전 | 계속 | - |
| **PreToolUse** | 도구 실행 전 | 허용 | 차단 |
| **PostToolUse** | 도구 실행 후 | 계속 | - |
| **Stop** | 응답 완료 후 | 계속 | - |
| **SessionStart** | 세션 시작 시 | 계속 | - |

### settings.json 설정 (공식 형식)

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx tsx .claude/hooks/protect-files.ts"
          }
        ]
      }
    ]
  }
}
```

### TypeScript Hook 템플릿

```typescript
#!/usr/bin/env npx tsx

interface HookInput {
  session_id: string;
  tool_name?: string;
  tool_input?: Record<string, unknown>;
}

async function main() {
  const input: HookInput = JSON.parse(await readStdin());
  if (shouldBlock(input)) {
    console.error("BLOCKED: reason");
    process.exit(2);
  }
  process.exit(0);
}

function readStdin(): Promise<string> {
  return new Promise((resolve) => {
    let data = '';
    process.stdin.on('data', chunk => data += chunk);
    process.stdin.on('end', () => resolve(data));
  });
}

main().catch(e => { console.error(e); process.exit(1); });
```

## 문제 해결

### Skill이 트리거되지 않음
1. description에 키워드 포함 확인
2. skill-rules.json 항목 확인
3. Hook 수동 테스트

### Hook이 실행되지 않음
1. settings.json 경로 확인
2. 실행 권한 확인 (`chmod +x`)
3. 수동 테스트로 stdin 처리 확인

### Agent가 작동하지 않음
1. .md 파일 존재 확인
2. 파일명과 agent 호출 일치 확인

## Testing Strategy

### Test Pyramid

```
                    /\
                   /  \     E2E Tests
                  /────\    (Critical Paths)
                 /      \
                /────────\  Integration Tests
               /          \ (Module 연동)
              /────────────\
             /              \ Unit Tests
            /────────────────\ (개별 함수)
```

### Test Levels

#### 1. Unit Tests
**목적**: 개별 함수/메서드 검증

**범위**:
- Helper 함수
- Utility 함수
- 순수 함수 (Pure Functions)

**실행**:
```bash
npm test -- --testPathPattern=unit
```

**커버리지 목표**: 80%+

**예시**:
```typescript
// unit-tests/helpers.test.ts
describe('formatOutput', () => {
  it('should format output correctly', () => {
    const input = { name: 'test', value: 123 };
    const result = formatOutput(input);
    expect(result).toEqual('test: 123');
  });
});
```

#### 2. Module Tests
**목적**: 모듈 단위 검증 (내부 함수들 조합)

**범위**:
- 모듈 내부 로직
- 모듈 인터페이스
- Mock 외부 의존성

**실행**:
```bash
npm test -- --testPathPattern=module
```

**커버리지 목표**: 75%+

**예시**:
```typescript
// module-tests/validator.test.ts
describe('ValidationModule', () => {
  it('should validate all fields', () => {
    const validator = new Validator();
    const result = validator.validate({ email: 'test@test.com' });
    expect(result.isValid).toBe(true);
  });

```

#### 3. Integration Tests
**목적**: 모듈 간 연동 검증

**범위**:
- 모듈 간 데이터 흐름
- API 호출 연동
- Database 연동
- MCP 서버 연동

**실행**:
```bash
npm test -- --testPathPattern=integration
```

**커버리지 목표**: 70%+

**예시**:
```typescript
// integration-tests/api.test.ts
describe('API Integration', () => {
  it('should fetch and process data', async () => {
    const api = new APIClient();
    const processor = new DataProcessor();

    const data = await api.fetch('/endpoint');

```

#### 4. E2E Tests
**목적**: 전체 플로우 검증

**범위**:

**실행**:
```bash

```

**커버리지 목표**: Critical Paths 100%

**예시**:
```typescript

    sessionId: string,
```

## Best Practices

### Testing
1. **Test Isolation**: 각 테스트는 독립적
2. **Fast Feedback**: Unit tests는 1초 이내
3. **Meaningful Names**: 테스트 이름으로 의도 파악
4. **AAA Pattern**: Arrange, Act, Assert
5. **DRY Principle**: 중복 제거 (setup/teardown)

### Memory Management
1. **Frequent Checkpoints**: Phase별 필수 저장
2. **Atomic Operations**: Checkpoint는 원자적 저장
3. **Backward Compatible**: Context 스키마 버전 관리
4. **Cleanup Policy**: 오래된 checkpoint 자동 정리
5. **Security**: 민감 정보 저장 금지

### Error Handling
1. **Graceful Degradation**: 부분 실패 허용
2. **Detailed Logging**: 에러 컨텍스트 기록
3. **Retry Logic**: Transient 에러 자동 재시도
4. **Rollback**: 실패 시 이전 checkpoint로 복원

```typescript
// autonomous-feature-builder 패턴
class FeatureBuilder {
  async execute(userRequest: string) {
    const sessionId = generateSessionId();

    // Phase 0: Research (if needed)
    if (requiresResearch(userRequest)) {
      await this.executePhase(sessionId, 0, async () => {
        return await researchCatalyst.execute(userRequest);
      });
    }

    // Phase 1: Context Analysis
    await this.executePhase(sessionId, 1, async () => {
      return await analyzeContext();
    });

    // Phase 2-5: ...

    return await getSessionResult(sessionId);
  }

  private async executePhase(
    sessionId: string,
    phaseNumber: number,
    phaseLogic: () => Promise<any>
  ) {
    // 1. Checkpoint 확인 (재개 시)
    const checkpoint = await loadCheckpoint(sessionId, phaseNumber);
    if (checkpoint?.phase.status === 'completed') {
      console.log(`✅ Phase ${phaseNumber} already completed`);
      return checkpoint.outputs;
    }

    // 2. Phase 실행
    console.log(`🔄 Executing Phase ${phaseNumber}...`);
    const outputs = await phaseLogic();

    // 3. Tests 실행
    await this.runTests(phaseNumber);

    // 4. Validation
    const validation = await this.validate(phaseNumber, outputs);

    // 5. Checkpoint 저장
    await saveCheckpoint({
      sessionId,
      phaseNumber,
      outputs,
      validation
    });

    // 6. Gate 검증
    if (!validation.passed) {
      throw new GateFailedError(`Phase ${phaseNumber} validation failed`);
    }

    return outputs;
  }

  private async runTests(phaseNumber: number) {
    const testMatrix = {
      1: ['unit'],
      2: ['unit', 'module'],
      3: ['unit', 'module', 'integration'],
      4: ['unit', 'module', 'integration', 'e2e']
    };

    const levels = testMatrix[phaseNumber] || [];

    for (const level of levels) {
      await this.runTestLevel(level);
    }
  }
}
```

## Best Practices

### Testing
1. **Test Isolation**: 각 테스트는 독립적
2. **Fast Feedback**: Unit tests는 1초 이내
3. **Meaningful Names**: 테스트 이름으로 의도 파악
4. **AAA Pattern**: Arrange, Act, Assert
5. **DRY Principle**: 중복 제거 (setup/teardown)

### Memory Management
1. **Frequent Checkpoints**: Phase별 필수 저장
2. **Atomic Operations**: Checkpoint는 원자적 저장
3. **Backward Compatible**: Context 스키마 버전 관리
4. **Cleanup Policy**: 오래된 checkpoint 자동 정리
5. **Security**: 민감 정보 저장 금지

### Error Handling
1. **Graceful Degradation**: 부분 실패 허용
2. **Detailed Logging**: 에러 컨텍스트 기록
3. **Retry Logic**: Transient 에러 자동 재시도
4. **Rollback**: 실패 시 이전 checkpoint로 복원
